# Уведомления Viber по номеру телефона

Mio! использует **Viber Business Messages через Infobip**. Получатель берётся из телефона бронирования; подписка на чат-бота и персональные ссылки не нужны.

## Когда отправляется сообщение

- «Подтверждено» — подтверждение после принятия брони сотрудником.
- «Отменено» и «Отменено гостем» — отмена брони.
- Повторное сохранение того же статуса не создаёт новое уведомление.
- «Подтверждено гостем», лист ожидания, визит без бронирования и миграция старых данных не запускают отправку.
- В форме брони должна быть включена галочка «Уведомлять гостя в Viber».
- Удаление записи не считается отменой: для уведомления выберите статус отмены.

Номер должен содержать код страны: например, `+37060000123`. Пробелы, скобки и дефисы допустимы, международный префикс `00` преобразуется в `+`. Номер без кода страны не дополняется автоматически.

## Подготовка Infobip

1. Создайте аккаунт Infobip и подключите Viber Business Messages. Зарегистрируйте отправителя ресторана и дождитесь одобрения.
2. Создайте API-ключ для отправки Viber, чтения шаблонов и журналов сообщений. Уточните доступные scopes у менеджера Infobip; для управления шаблонами документация указывает `viber-bm:manage`.
3. Зарегистрируйте два **TRANSACTIONAL** шаблона. Готовые запросы регистрации находятся в `config/viber-templates/accepted.json` и `cancelled.json`. Отправлять их следует через ваш аккаунт Infobip на `POST /viber/1/senders/{sender}/templates`. Mio! не создаёт платный аккаунт и не регистрирует отправителя автоматически.
4. Оба шаблона должны получить статус `APPROVED`. Сохраните их `templateId`.
5. Добавьте в `server/.env`:

```dotenv
INFOBIP_BASE_URL=https://your-account.api.infobip.com
INFOBIP_API_KEY=your-api-key
VIBER_INFOBIP_SENDER=YourApprovedSender
VIBER_INFOBIP_ACCEPTED_TEMPLATE=accepted-template-id
VIBER_INFOBIP_CANCELLED_TEMPLATE=cancelled-template-id
VIBER_INFOBIP_LANGUAGE=ru
```

Укажите Base URL из аккаунта Infobip. API-ключ хранится только на сервере. Токен обычного чат-бота `VIBER_BOT_TOKEN` для отправки по телефону не используется.

6. Перезапустите Mio!. Откройте **Интеграции → Сервисы → Viber**.
7. Нажмите **«Проверить подключение и шаблоны»**, затем **«Включить уведомления»**. Активация повторно проверяет одобрение, язык и параметры обоих шаблонов. Старые подтверждённые брони не рассылаются задним числом.
8. Для первой живой проверки создайте бронь со своим номером, включите уведомления и установите «Подтверждено». Эта операция отправляет настоящее сообщение через ваш платный аккаунт Infobip. Отмена этой брони отправит второй шаблон.

## Шаблоны

Подтверждение использует параметры `name`, `restaurant`, `date`, `time`, `guests`.

```text
Здравствуйте, {{name}}! Ваше бронирование в {{restaurant}} подтверждено.
Дата: {{date}}, время: {{time}}. Гостей: {{guests}}. До встречи!
```

Отмена использует `name`, `restaurant`, `date`, `time`, `phone`.

```text
Здравствуйте, {{name}}! Ваше бронирование в {{restaurant}} на {{date}} в {{time}} отменено.
Если это ошибка, свяжитесь с рестораном: {{phone}}.
```

Текст редактируется и одобряется в Infobip. Если меняете имена параметров, нужно согласовать их с адаптером Mio!. Никакой автоматической замены на SMS или рекламные свободные тексты нет.

## Очередь и доставка

Уведомление записывается в SQLite в той же транзакции, что и изменение бронирования. При ошибке сохранения оно не отправляется. Локальный сервер обрабатывает очередь каждые 3 секунды, пока запущен.

В сохранённой брони показаны очередь, ошибки и состояние доставки. «Принято Infobip» означает принятие платформой, а не доставку на телефон. Кнопка **«Проверить доставку»** читает журнал Infobip; «Доставлено гостю» появляется только при подтверждении `DELIVERED_TO_HANDSET`.

Если ответ об отправке потерян, запись получает состояние **«Отправка не подтверждена»**. Повтор автоматически не выполняется: обновите статус и проверьте журнал Infobip. После перезапуска прерванная отправка также не повторяется вслепую. Кнопка повтора доступна только после подтверждённой ошибки или исправления телефона.

Если бронь отменена до отправки подтверждения, старое уведомление помечается неактуальным, а отправляется отмена. Если телефон исправлен после пропуска уведомления, сохраните бронь и нажмите повтор после исправления.

Отправка работает через исходящие HTTPS-запросы. Для этой реализации публичный сервер или туннель не требуются.

## Проверка разработки

Серверные тесты используют подменённый API Infobip и тестовую SQLite; сообщения реальным гостям не отправляются. Тесты проверяют переходы статусов, телефон, шаблоны, очередь, повторные сохранения, сбои, перезапуск, проверку доставки и защиту API. Живую отправку нужно проверить после подключения Infobip.
