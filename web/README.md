# Mio! RU

Модульное локальное приложение управления рестораном. Переработано из существующего проекта с сохранением данных и рабочих сценариев.

## Запуск

Для обычной работы откройте `../Запустить Mio!.command` или выполните из папки Mio! `npm start`. Сайт: http://127.0.0.1:4175. Данные сохраняются сервером в SQLite.

Для разработки нужен Node.js 24+. Установите зависимости (`npm ci`), запустите сервер в соседней папке и выполните:

```sh
npm run dev
npm run check       # проверка кода, тесты, сборка
npm run format:check
npm run build       # сайт в dist/, выдаётся сервером
npx playwright install chromium
npm run test:e2e
```

Vite перенаправляет `/api` на http://127.0.0.1:4175. Без сервера ранее подключённый клиент доступен для просмотра кеша, запись приостановлена. Для автономного клиента, никогда не подключённого к серверу, сохранён прежний режим localStorage.

Браузерные E2E-сценарии проверяют прежний автономный режим на отдельном адресе; API и SQLite проверяются отдельными серверными тестами. Можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE` для установленного Chromium.

## Структура

- `src/app/` — запуск и соединение модулей.
- `src/routes/` — единый маршрутизатор, динамическая загрузка страниц и их жизненный цикл.
- `src/pages/` — контроллеры страниц.
- `src/components/` — оболочка, навигация, календарь, диалоги, уведомления, иконки.
- `src/features/` — бронирования, план и редактор залов, гости, формы пользователей, отчёты, импорт, локальные справочники.
- `src/services/` — хранение, нормализация данных, проверки бронирований, CSV, общие фильтры и группировка.
- `src/config/` — исходные настройки, меню и схемы справочников.
- `src/styles/` — стили по областям интерфейса и общая тема.
- `tests/unit/`, `tests/e2e/` — проверки правил и пользовательских сценариев.
- `docs/` — аудит, архитектура, проверка и использованные материалы.

## Возможности

Бронирования и лист ожидания; редактирование, перенос и удаление записей; статусы, поиск, фильтры, группировка, сортировка; пять представлений бронирований; основной зал и терраса; редактор с дополнительными залами и фоновыми изображениями; блокировки столов и времени; официанты и назначения; гости, теги, категории, пользовательские поля; профиль ресторана и локальные настройки пользователей и прав; CSV-импорт с проверкой и предварительным просмотром; экспорт отчётов и резервных данных; локальное редактирование смен, событий, шаблонов, кампаний, сегментов и других справочников.

## Границы текущей версии

Это интерфейс с локальным сервером. Записи и настройки хранятся в серверной базе; фильтры и текущая дата принадлежат браузеру. Серверная авторизация и подключение платежей, POS, WhatsApp, SMS, почты и Navi пока отсутствуют. Интерфейс показывает фактическую недоступность внешних подключений.

Смены, события, объединения столов, программы лояльности и шаблоны сохраняются на сервере. Исполнение кампаний, продажа билетов и действия внешних провайдеров требуют соответствующих интеграций. PIN сохраняется хешем, но роли и PIN ещё не обеспечивают контроль доступа. Полное совпадение всех состояний оригинального SaaS не подтверждено: исследование охватывает 21 маршрут и не содержит серверного кода.

Подробности хранения, миграции и API: [сервер](../server/README.md).

## Резервная копия и восстановление

До изменений создан архив `mio-web-before-20261013.tar.gz` в папке outputs/backups текущей задачи. Он содержит три исходных файла без изменений. Контрольная сумма указана в `docs/AUDIT.md`.

Чтобы восстановить исходники, распакуйте архив в отдельную папку, проверьте его содержимое, затем замените текущий `web/`. Архив исходников не содержит localStorage браузера. Его данные экспортируются отдельно в разделе «Управление аккаунтом → Настройки».

Подробности: [архитектура](docs/ARCHITECTURE.md), [аудит](docs/AUDIT.md), [проверка](docs/VERIFICATION.md).
